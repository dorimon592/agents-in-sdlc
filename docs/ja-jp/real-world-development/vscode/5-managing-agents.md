GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat は、作業がローカルでリアルタイムに進むため、ツールの呼び出しやファイルの編集を逐次確認できます。差分をインラインでレビューし、変更を個別に採用または取り消し、フォローアップのプロンプトで会話を案内して作業を調整できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして採用します。
- セッションの途中でエージェントに指示を追加し、ハイコントラストに加えてライトモードの切り替えを依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中、デザインチームから追加のリクエストがありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにしたいとのことです。新しい会話を最初から始めずに、進行中のセッションに指示を追加して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調べているファイル、実行するコマンド、提案する編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの呼び出しを確認します。ファイルの読み込みや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消し、エージェントに別の方法を試させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの許可を求められると、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替え機能を追加します。チャットセッションを続けることで、エージェントは前の作業のコンテキスト（変更したコンポーネント、スタイルの方針、local storage を使った設定の保存方法など）を維持できます。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

    ```plaintext
    よくできました。次に、ハイコントラストの切り替えと並べてライトモードの切り替えを追加してください。ライトモードも同じ方法で実装し、local storage に保存して、同じ UI 領域から利用できるようにしてください。ハイコントラストモードとライトモードは個別に有効化できるようにしてください。
    ```

2. エージェントは前回の変更を調べ、ライトモードを追加する提案をします。
3. ハイコントラストモードの場合と同じように、新しい編集をレビューします。各差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば、トグル UI を好ましくない方法でリファクタリングしようとする場合）は、チャット入力欄の横にある **Stop** ボタンで停止して、説明を加えたフォローアップメッセージを送信します。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すより短時間で調整できます。「CSS を簡潔にする。セレクターの重複ではなく CSS 変数を使う」「トグルを 3 つに増やさず、既存の設定パネルにライトモードを追加する」「両方の切り替えにキーボードショートカットも追加する」など、調整、修正、範囲の拡張を依頼できます。

## 変更されたファイルをまとめてレビューする

作業をコミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更したファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティの指針（ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など）が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して案内しました。ファイルの編集を個別にレビューし、変更を採用または取り消し、コンテキストを失わずに作業を広げるフォローアッププロンプトを送りました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法
- ファイルの編集を個別に採用または取り消す方法
- フォローアッププロンプトで進行中のセッションを案内する方法

次の[レッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが作成した変更をレビューします。
